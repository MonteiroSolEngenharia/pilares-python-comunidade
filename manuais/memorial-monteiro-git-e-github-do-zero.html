GitHub Desktop é só a interface visual para você não digitar comandos no terminal.

1

O que é um Repositório (repo)

Um repositório é uma pasta do seu projeto que você "ligou" ao Git. Cada projeto seu = um repo separado.

⚠️ Não existe controle de acesso por pasta dentro do mesmo repo. Quem tem acesso ao repositório, vê tudo dentro dele. Para separar o que é público do que é privado, você precisa de repositórios diferentes.
📁 propostas-comerciais-monteiro   → privado, só você
📁 pilares-python-aulas            → público, comunidade
📁 agenda-automatizada             → privado ou público, como preferir
2

O ciclo básico: Commit → Push

  1. Edite os arquivos normalmente no VS Code
  2. Commit = tira uma "foto" do que mudou, com uma mensagem explicando
  3. Push = envia essa foto para a nuvem (GitHub.com)

No GitHub Desktop, isso é 3 passos visuais:

  1. Aba Changes (esquerda) mostra os arquivos que mudaram
  2. Escreva uma frase curta no campo Summary
  3. Clique em Commit to [branch] → depois Push origin (topo)
💡 Dica de ouro: comite toda vez que terminar algo, mesmo pequeno. É isso que evita esquecer tudo depois de 2 meses.

Público x Privado — dando acesso à comunidade

Ao criar um repositório, o GitHub pergunta:

  • Public: qualquer pessoa no mundo vê, até sem conta
  • Private: só você e quem for convidado
✅ Solução para seu caso: crie um repo separado e público (ex: pilares-python-aulas) só com o que quer compartilhar com estagiários/comunidade. Seus projetos de trabalho (como o Propostas-Comerciais-Monteiro) ficam em repos privados.

Dar acesso a pessoas específicas (sem ser público)

Repo Private → aba Settings no GitHub.com → Collaborators → adicionar e-mail/usuário da pessoa.

5

Retomando um repo esquecido há meses

  1. Abra o GitHub Desktop
  2. File → Add Local Repository → selecione a pasta antiga
  3. Ele mostra tudo que mudou desde a última vez
  4. Escreva uma mensagem tipo Atualização após retomada do projeto → Commit
  5. Clique em Push origin
💡 A partir daí, retome o hábito: terminar algo relevante → commit + push, sempre.

Dúvidas Frequentes

O que é essa "branch" (feature/exemplo)?
É uma versão paralela do projeto, separada da principal (main). Serve para testar algo sem arriscar quebrar o que já funciona. Depois você pode "juntar" (merge) de volta no main quando estiver pronto.
Preciso dar push toda vez que faço commit?
O commit só salva localmente. Sem o push, isso não vai para o GitHub.com — e some se você reinstalar o computador, por exemplo. Sempre dê push depois do commit.
Posso ter vários arquivos num commit só?
Sim, o GitHub Desktop agrupa tudo que você mudou desde o último commit. Mas é boa prática comitar por "assunto" (ex: só o que é da proposta web, separado de outra mudança não relacionada).
Dei push errado ou quero desfazer algo, e agora?
Dá para reverter — mas é mais delicado. Quando acontecer, me chame com o print da tela e eu te oriento o comando certo para não perder nada.

  1. Editou algo importante → abra o GitHub Desktop
  2. Veja os arquivos mudados na aba Changes
  3. Escreva uma mensagem curta no Summary
  4. Clique em Commit
