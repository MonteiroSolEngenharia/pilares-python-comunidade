O que é um ambiente virtual (venv)?

É uma pasta isolada dentro do seu projeto que tem sua própria cópia do Python e das bibliotecas instaladas. Assim, cada projeto pode ter versões diferentes de bibliotecas sem conflitar com outros projetos ou com o Python "global" do computador.

💡 Pense assim: cada projeto Python importante merece sua "caixa de ferramentas" própria, sem misturar com a de outro projeto.
?

Quando criar um ambiente virtual?

SituaçãoCriar venv?
Começando um projeto novo (script de agenda, automação, etc.)✅ Sim, sempre
Projeto que usa bibliotecas externas (numpy, matplotlib, google-api, etc.)✅ Sim
Script simples, de uma linha, sem biblioteca externaOpcional
Vai dar o projeto para outra pessoa / rodar em outro computador✅ Sim (facilita recriar o ambiente)
⚠️ Nunca instale bibliotecas direto no Python "global" do Windows para projetos sérios — isso gera conflito quando dois projetos pedem versões diferentes da mesma biblioteca.
1

Criar o ambiente virtual

Abra o terminal (PowerShell) na pasta do seu projeto, por exemplo:

cd C:\PilaresPython

Rode o comando que cria a pasta .venv com o ambiente isolado:

python -m venv .venv
✅ Isso cria uma pasta .venv dentro do projeto. Você só faz isso uma vez por projeto.
2

Ativar o ambiente virtual

Toda vez que for trabalhar no projeto, ative o ambiente:

.venv\Scripts\activate

Se der certo, o prompt do terminal muda e passa a mostrar (.venv) no início da linha:

(.venv) PS C:\PilaresPython>
⚠️ Se o PowerShell bloquear com erro de "política de execução", rode uma vez:
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
3

Instalar bibliotecas dentro do ambiente

Com o (.venv) ativo, instale só o que esse projeto precisa:

pip install numpy matplotlib

Para o projeto da Agenda Google, por exemplo:

pip install google-auth-oauthlib google-api-python-client
💡 Cada projeto tem sua própria lista de bibliotecas — instalar aqui dentro não afeta outros projetos nem o Python global.

Guardar a lista de bibliotecas (opcional, mas recomendado)

pip freeze > requirements.txt

Isso salva um arquivo com todas as bibliotecas e versões usadas. Em outro computador, basta rodar:

pip install -r requirements.txt
4

Saindo e voltando ao ambiente

✅ Para sair:
deactivate
✅ Para voltar depois:
cd C:\PilaresPython
.venv\Scripts\activate

Repare: você só cria o ambiente (python -m venv .venv) uma vez. Depois disso é só ativar e desativar quando for usar.

Dúvidas Frequentes

Se eu apagar a pasta .venv, perco meu código?
Não. O .venv só guarda o Python e as bibliotecas instaladas. Seu código (os arquivos .py) fica fora dessa pasta, no projeto. Se apagar o .venv, só precisa criar de novo e reinstalar as bibliotecas.
Preciso criar um venv novo para cada script?
Não necessariamente. Se os scripts fazem parte do mesmo projeto (ex: automações da agenda), pode usar o mesmo .venv para todos eles. Crie um venv novo quando o projeto for de outra natureza ou precisar de versões diferentes de bibliotecas.
Como sei se estou "dentro" ou "fora" do ambiente virtual?
Olhe o início da linha do terminal. Se aparecer (.venv) antes do caminho da pasta, você está dentro. Se não aparecer, está usando o Python global do Windows.
Posso ter vários ambientes virtuais no mesmo computador?
Sim, sem limite. Cada pasta de projeto pode (e deve) ter o seu próprio .venv, totalmente isolado dos outros.

Resumo Rápido para o Dia a Dia

Criando um projeto novo (primeira vez):

  1. cd C:\CaminhoDoProjeto
  2. python -m venv .venv
  3. .venv\Scripts\activate
  4. pip install bibliotecas-que-precisar

Voltando a um projeto já existente:

  1. cd C:\CaminhoDoProjeto
  2. .venv\Scripts\activate
  3. Rodar o script: python nome_do_script.py
A criação (passo 1 e 2 do primeiro bloco) só é feita uma vez por projeto. No dia a dia, você só ativa e roda.
